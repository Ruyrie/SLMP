## 三、接口与 JSON（与 App 对齐的硬性要求）

1. **统一响应** `{code, message, data, trace_id}`，成功 `code=0`、`message="ok"`。**HTTP 状态码 = 错误码前三位**（成功 200、40001→400、42206→422）。App 只有在非 2xx 时才能拿到错误的 data（field_errors、reason 等）。
2. **40101、40104 必须是 HTTP 401 且带 JSON 体**，否则 App 不会刷新令牌、不会清登录态。刷新令牌（API-A06）失败只能返回 40104。
3. **不要返回 204**；所有接口返回 200 + JSON。App 用 `unwrap()` 取数据的查询接口，`data` 不能为 null（空列表返回 `[]`，空对象返回 `{}`）。
4. **40001** 的 `data.field_errors` 是数组 `[{field, message}]`，field 用请求 JSON 的 snake_case 路径（`items[0].weight`）。
5. **命名**：JSON 一律 snake_case（Jackson SNAKE_CASE），包括请求体；查询参数也是 snake_case（`start_date`、`biz_type`），框架负责绑定到 XxxQuery 的驼峰属性。Map 的键（如 tab_counts）原样输出。
6. **布尔 is_ 字段**：App 要 `is_breeding`、`is_system`、`is_current` 等。VO 中写成包装类型 `private Boolean isBreeding;`（Lombok 生成 getIsBreeding → is_breeding），**不要用基本类型 boolean isXxx**（会输出成 breeding）。
7. **带数字的字段**按 Gson 规则：`recent7DoneDays` → `recent7_done_days`（Jackson 默认一致）；个别 App 显式指定的名字（如 `usage_7d_total`）用 `@JsonProperty`。
8. **时间**：datetime `yyyy-MM-dd HH:mm:ss`，date `yyyy-MM-dd`，时刻 `HH:mm`（LocalTime），月份 `yyyy-MM`（YearMonth）；全部北京时间，不输出 ISO 的 T 和时间戳。业务代码取当前时间一律用 `BeijingTime.now() / today()`。
9. **数字**：金额、重量、数量用 BigDecimal 输出为 JSON 数字（不用科学计数法）；ID 用 Long 输出为数字。
10. **空值**：值为 null 的字段不输出；必需字段（如 version、计数）必须有值。集合字段默认空集合而不是 null。
11. **枚举**：输出大写编码，另带 `xxx_text` 中文名；但只按 App 现有字段输出（有的只有编码、有的只有文字，以 App VO 为准）。
12. **员工字段裁剪**：VO 中单价、均价、金额、成本、利润、收入类字段标 `@ManagerView`，员工请求时序列化直接省略该键；整模块员工无权的接口用 `@FarmRoles({OWNER, MANAGER})` 返回 40303。
13. **分页**：`PageVO`（list、total、page、size、has_more、tab_counts），可继承 PageVO 在 list 同级追加字段；page 从 1 开始，size 默认 20、最大 100。部分接口 data 直接是数组（U09、U10、U14 等），以 App 为准。
14. **路径**：用户端 `/api/v1/...`，管理端 `/admin/v1/...`。固定路径与 `{id}` 路径并存（`/todos/today` 与 `/todos/{id}`），`{id}` 写成 `{id:\d+}`。没有请求体的 POST 要能接受空体、无 Content-Type。DELETE 不带请求体，version 放查询参数。
15. **请求头**：`Authorization: Bearer`、`X-Farm-Id`、`X-Client`（APP_ANDROID / WEB / ADMIN_WEB）、`X-App-Version`、`Idempotency-Key`（不一定是 UUID）。App **不发** X-Trace-Id，服务端生成并在响应头 `X-Trace-Id` 和 body 的 trace_id 中返回。`/farms/{farmId}/...` 以路径为准（请求头可能缺失或是旧养殖场）。
16. **App 匹配 message 文案的地方**（文案必须与文档一致）：“已经注册”“协议已更新”“过期”“本胎已登记产仔”“已由”“库存已变化”。
17. **超时**：App 普通请求读超时 30 秒，接口必须在 30 秒内返回；SSE 读 180 秒；导出读 45 秒。
18. 同一接口在服务端文档与 App 中写法不同时，以 App 当前代码为准；App 的 Retrofit 接口在各组件 `data/*Api.java`，VO 在 `model/vo`，Mock 样例在 `src/debug/assets/mock`。

## 四、框架用法（第 0 批提供）

| 需求 | 用法 |
|---|---|
| 不需要登录 | Controller 类或方法加 `@PublicApi` |
| 需要当前养殖场 | `@RequireFarm`（默认 GET 允许 NORMAL、DISABLED，写操作只允许 NORMAL；可用 allowStatus 覆盖）；Service 里用 `FarmContext.require()` 取角色、负责栏舍 |
| 限定角色 | `@FarmRoles({FarmRole.OWNER, FarmRole.MANAGER})`（隐含 @RequireFarm），不符返回 40303 |
| 员工栏舍范围 | `FarmContext.checkPen(penId)`，越出返回 40304；跨养殖场或不存在一律 40401（`Asserts.found(x)`） |
| 强制步骤期间可调用 | `@AllowForcedStep` |
| 管理端权限点 | `@AdminPermission("WA-R01:HANDLE")`，不符返回 40308 |
| 幂等 | 新增类接口加 `@Idempotent` |
| 限流 | `@RateLimit(key = "login", limit = 20, by = LimitBy.IP)`，可重复标注 |
| 留痕 | `@OpLog(...)` 或注入 `OperationLogRecorder` |
| 定时任务 | `@Scheduled(cron = "...", zone = "Asia/Shanghai")` + `@JobLock("任务名")` |
| 业务异常 | `throw new BizException(ErrorCode.XXX, "具体文案")`，需要 data 时 `.with("reason", "EXPIRED")` |
| 当前用户 / 管理员 | `UserContext.requireUserId()`、`AdminContext.requireAdminId()` |
| 扩展点（由业务模块实现） | `UserAuthStateLoader`（模块01）、`FarmMemberLoader`（模块02）、`AdminAuthStateLoader`（管理端-04）、`OperationLogRecorder`（公共能力） |
| 外部服务 | 注入 zhimu-integration 的 `AiGateway`、`SmsClient`、`PushClient`、`AmapClient`、`ObjectStorage`、`MediaProcessor`、`IpRegionResolver` |
| 查询参数对象 | 控制器参数写 `@Valid XxxQuery query`，**不要加 @ModelAttribute**（加了会走 Spring 默认绑定，snake_case 参数绑不上）；简单参数用 `@RequestParam("biz_type")` 显式写 snake_case 名 |
| Mapper | 放在 `com.zhimu.server.**.mapper` 包下即可被扫描，不用标 @Mapper；多表查询写 `resources/mapper/<模块>/XxxMapper.xml` |
| 养殖场表 | 实体类标 `@FarmScoped`（framework.mybatis），多租户插件才会自动加 farm_id 条件；跨养殖场查询用 `TenantSkip.call(() -> ...)` 后自行按养殖场 ID 过滤；只在 XML 中出现的表用 `FarmTableRegistry.register` 登记 |
| 实体基类 | `BaseEntity`（id、created_at、updated_at）、`AuditEntity`（再加 created_by）；deleted 用 `@TableLogic`、version 用 `@Version` 在实体中自行声明 |
| 令牌与会话 | 用户端：`UserTokenService`（issue / refresh / revokeAll / revokeClient）、`WebRefreshCookie`、`AuthStateCache.evict`；管理端：`AdminSessionService`；成员缓存：`FarmMemberCache.evict / evictFarm` |
| 养殖场状态规则 | `@RequireFarm` 默认：GET 允许 NORMAL、DISABLED，写操作只允许 NORMAL；模块规则不同的接口必须显式写 allowStatus（例如模块02 的 F02、F06–F08 允许 PENDING、REJECTED） |
| 切面顺序 | 限流（10）→ 幂等（20）→ 业务 → 留痕（最内层）；幂等重放命中时不重复留痕 |
| 异步 | `@Async` 默认用虚拟线程池 taskExecutor，另有 pushExecutor、aiExecutor、exportExecutor；上下文与 MDC 自动传递到异步线程（TenantSkip 不传递） |
| 扩展点实现位置 | `UserAuthStateLoader` 只在 `biz.account`、`FarmMemberLoader` 只在 `biz.farm`、`OperationLogRecorder` 只在 `biz.common`、`AdminAuthStateLoader` 只在管理端-04；每个 SPI 全仓库只能一个 Bean（`ObjectProvider.getIfAvailable()` 多候选会启动失败） |
| 鉴权状态缓存 | `auth:state:{user_id}` 的 4 个字段只能由框架序列化；模块01 只调 `AuthStateCache.evict(userId)`，不要自行写扩展结构 |
| 养殖场上下文 | 不要给 `FarmContext.FarmMember` 加字段（它是 Redis 缓存契约）；需要 owner_user_id 时在业务查询里取 |
| 操作留痕 | `t_operation_log` 没有 `updated_at/deleted/version`，实体不要继承 `BaseEntity`/`AuditEntity`；需要与业务同事务时直接注入 `OperationLogRecorder`，不要只依赖 `@OpLog` 切面 |
| 未登录接口幂等 | `@Idempotent` 需要 userId/adminId，A03/A09/A10 等未登录接口实际不生效；用唯一索引与业务校验防重，不缓存恢复码明文 |
| 事务提交后 | 缓存失效、发事件、推送用 `framework.tx.AfterCommit.run(...)`，不要直接在事务内执行 |
| 管理端边界 | 第 1 批只写管理端要调用的 Service 方法，不写 `/admin/v1` Controller；`AdminAuthStateLoader` 未实现时权限点校验不生效 |

## 五、数据库

- 表、字段、索引完全按各模块服务端文档与 05 号文档；字符集 utf8mb4、排序规则 utf8mb4_0900_ai_ci，引擎 InnoDB，不建外键。
- 公共字段：id BIGINT UNSIGNED 自增、created_at / updated_at（自动填充）、created_by（自动填充当前用户或管理员，系统为 0）、deleted（逻辑删除）、version（乐观锁）。
- 属于养殖场的表带 farm_id，多租户插件在有 FarmContext 时自动加条件；“全部养殖场”视角用 `TenantSkip` 显式关闭后自行按养殖场 ID 列表过滤。
- **Flyway 脚本版本号分配**（已执行的脚本不再修改，结构变更另起新版本）：

| V1_01 | 模块01 账号 | V1_22 | 管理端-02 内容运营 |
| V1_02 | 模块02 养殖场 | V1_23 | 管理端-03 基础数据 |
| V1_03 | 模块03 今日与消息 | V1_24 | 管理端-04 用户与系统 |
