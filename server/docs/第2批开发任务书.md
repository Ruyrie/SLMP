## 三、App 兼容口径（管理端-03 必须按此落数据）

1. 品类 ID 101 育肥猪、102 种猪、201 肉鸡、301 肉牛；品种 1101 杜长大、1102 长白、1201 长大二元、2101 白羽肉鸡、3101 西门塔尔。`count_unit`：101/102/301=HEAD、201=BIRD；`species_text` 精确“猪/禽/牛/羊”。
2. 1201：`gestation_days=114`、`pregnancy_check_days=21`、`offspring_breed_id=1101`、`has_std_weight=false`、**`has_feed_std=true`**（按 App Mock，种猪不设标准体重但设饲喂标准）；2101 `incubation_days=21`；1101/1102/2101/3101 的 has_* 与 App Mock 一致。
3. U11 的 `measure_unit` 存/出代码 `G/ML/L/DOSE/KG`，另可加 `measure_unit_text`；不要存“克/毫升/头份”。
4. VACCINATE_METHOD 饮水用 `WATER`（App Mock），不要用 `DRINKING`。
5. FEED_TYPE 用并集 9 项：COMPLETE、NURSERY、CONCENTRATE、PREMIX、RAW、ENERGY、PROTEIN、ROUGHAGE、ADDITIVE。
6. PAYMENT_METHOD 作为第 8 类字典，U10 支持，D49 返回 8 类（+ 可选财务分类后续补）。
7. 字典项 ID 按类型分段（PEN 501–、DEATH 601–、SYMPTOM 401–、FEED 3101–、VACC 701–、DISINFECT 721–、SCRAP 3201–、PAYMENT 3301–），不要沿用 Mock 中跨类型重复的 701–704。
8. U10 在未传 species/category_id 且带 X-Farm-Id 时，PEN_TYPE/VACCINATE_METHOD 按当前养殖场主要品类的畜种推断过滤；其他字典返回全部启用项。
9. U09/U10/U12/U13 不挂 `@RequireFarm`；U11 要求养殖场上下文，所有者/场长可调，员工 40303。
10. U12/U13 App 主代码没有调用，按模块06/07 文档实现并在报告里注明“无 App 联调”；U13 的 options 追加 `sort_no`。

## 四、管理端认证与只读 Mapper

- `AdminAuthState` 已增加 `invalidReason`；`AdminAuthInterceptor` 已支持 40106 的 `data.reason`、`@NoSessionRenew`、loader 缺失时对 `@AdminPermission` fail-closed 40308。4A 实现 `AdminAuthStateLoader`（唯一 Bean），权限缓存键用 `admin:perm:{role_id}`，会话索引沿用 `admin:session:index:{admin_id}`。
- 管理端请求要求 `X-Client: ADMIN_WEB` 的校验由 4A 在登录/业务 Service 或 Controller 层尽量补；若与现有框架测试冲突，可先按文档记录为部署/网关约束。
- 管理端只读查询允许在 `admin.system.mapper.readonly`、`admin.audit.mapper.readonly` 写 SELECT XML 直接读 `t_user/t_farm/t_farm_member/t_farm_audit/t_farm_change/t_account_recovery/t_recovery_verify_log/t_change_request/t_operation_log`；只读、禁止写；必须显式写 `deleted=0`/`active_flag=1`/`pending_flag`，手机号统一打码；写操作仍调第 1 批 Service。此例外已获用户批准。
- 管理员/用户密码用 BCrypt；初始/重置密码 10 位，`must_change_password=1`，24h；短信本批只置 PENDING，不发送、不写日志。S22/S24 在 dev profile 可在响应中返回 `temp_password` 供联调，生产不返回。
