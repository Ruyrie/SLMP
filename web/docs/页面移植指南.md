# 原型页面移植指南（从 WU-xxx.js 到正式页面）

> 每个页面按同一流程做：**读原型 → 读文档 → 定接口 → 写 store → 写页面 → 截图对照 → 修**。
> 原型只是视觉与交互参考，数据、业务规则、校验必须来自 App / 服务端。

## 一、原型文件怎么看

| 文件 | 用途 |
|---|---|
| `原型导出/Web端/智牧通Web原型/pages/user/WU-L02.js` | 页面模板、示例数据、页面专用 CSS、状态定义 |
| `原型导出/Web端/智牧通Web原型/screenshots/WU-L02-list.png` | 视觉基准（1440×900） |
| `原型导出/Web端/智牧通Web原型/zw.js` | 公共组件定义（属性、插槽），正式工程已迁移 |
| `原型导出/Web端/智牧通Web原型/zw.css` | 公共样式，正式工程已复制 |
| `.tech-prep/text/Web端_用户端_模块04-...-Web端UI设计文档.md` | 页面目标、字段、交互、接口编号、状态、文案 |
| `.tech-prep/text/Android端_模块04-...-UI设计文档.md` | 业务规则、校验、边界与文案（冲突以 App 为准） |
| `server/zhimu-biz/.../vo/*.java` | 真实字段名与类型（snake_case） |

页面模板里可以直接复用的部分：页面结构、`zw-*` 组件用法、页面专用 CSS、表格列顺序、空状态/错误状态文案。**不能复用**：写死的示例数字、`$is('state')` 判断、mock 数组、`methods` 里的假逻辑。

## 二、移植步骤

### 1. 建文件
```
apps/user/src/views/herd/PenListView.vue
apps/user/src/stores/herd/penList.ts
apps/user/src/api/herd.ts          # 已存在则追加
```
路由：打开 `apps/user/src/router/herd.ts`，把 `WU-L02` 的 `placeholder` 换成 `() => import('@/views/herd/PenListView.vue')`。路径、名称、meta 不改。

### 2. 把模板迁进 SFC
- 复制原型 `template` 的内层内容（不含 `<zw-shell>` 外的部分）。
- 外层加 `<zw-shell side="user" active="WU-L02" :crumbs="['生产管理','栏舍管理']">`。
- 原型 `css` 字段改为 `<style scoped>`，类名保留。
- 原型里的 `v-if="$is('xxx')"` 改成真实状态；`{{ n(870) }}` 改成后端字段 + `formatNumber`。
- 原型里的 `v-model` 绑定到 store 的 query/form；点击事件改成 store action。

### 3. 定接口（先查再写）
1. `docs/api/endpoints.csv` 搜路径；
2. 打开 Controller 看 `@GetMapping`、`@RequestParam`；
3. 打开 VO 看字段；
4. 用真实请求确认返回。

例：WU-L02 栏舍列表
```bash
# 登录
POST /api/v1/auth/login/password  {"phone":"13800006620","password":"Zmt12345"}  X-Client: WEB
# 列表
GET /api/v1/pens?page=1&size=20&keyword=  Authorization: Bearer ...  X-Farm-Id: 1001
```
字段以 `PenItemVO` / `PenListVO` 为准。

### 4. 写 store
按 `开发约定.md` 第五节模板。要点：
- `query` 与网址查询参数同步（可选，列表筛选建议做）；
- 请求取消：`this.controller?.abort(); this.controller = new AbortController()`；
- 状态机：`loading → ready/empty/filtered_empty`，失败 `error`，403 `forbidden`；
- 表单抽屉：`openCreate/openEdit/detail` + `form/formErrors/submitting`；
- 提交成功：关闭抽屉、`useUiStore().toast('已保存')`、`fetchList()`。

### 5. 写页面四态
```vue
<template>
  <zw-shell side="user" active="WU-L02" :crumbs="['生产管理', '栏舍管理']">
    <zw-page-head title="栏舍管理" desc="维护栏舍容量、负责员工与停用状态">
      <template #actions>
        <v-btn variant="outlined" prepend-icon="refresh" @click="store.fetchList()">刷新</v-btn>
        <v-btn color="primary" prepend-icon="add" @click="store.openCreate()">新增栏舍</v-btn>
      </template>
    </zw-page-head>

    <zw-notice v-if="store.status === 'forbidden'" type="warning" title="无权查看">
      {{ store.error || '你没有该页面的查看权限' }}
    </zw-notice>

    <zw-card flush>
      <div class="zw-toolbar">
        <div class="zw-toolbar-l">
          <v-text-field v-model="store.query.keyword" class="zw-w-240" placeholder="搜索栏舍名称" prepend-inner-icon="search" @keydown.enter="store.fetchList()" />
        </div>
      </div>
      <v-skeleton-loader v-if="store.status === 'loading'" type="table-row@6" />
      <zw-empty v-else-if="store.status === 'error'" icon="cloud_off" title="加载失败" :desc="store.error" tone="error">
        <v-btn variant="outlined" @click="store.fetchList()">重新加载</v-btn>
      </zw-empty>
      <zw-empty v-else-if="store.status === 'empty'" icon="fence" title="还没有栏舍" desc="先新增一个栏舍，再登记批次">
        <v-btn color="primary" @click="store.openCreate()">新增栏舍</v-btn>
      </zw-empty>
      <template v-else>
        <v-data-table :headers="headers" :items="store.list" hide-default-footer />
        <div class="zw-table-foot"><zw-pager :total="store.total" :page="store.query.page" :size="store.query.size" /></div>
      </template>
    </zw-card>

    <zw-drawer v-model="store.drawer" :title="store.editing ? '编辑栏舍' : '新增栏舍'" width="560">
      <!-- 表单 -->
      <template #foot>
        <v-btn variant="outlined" @click="store.drawer = false">取消</v-btn>
        <v-btn color="primary" :loading="store.submitting" @click="store.submit()">保存</v-btn>
      </template>
    </zw-drawer>
  </zw-shell>
</template>
```

## 四、页面专用注意事项

| 模块 | 注意 |
|---|---|
| 01 账号 | 注册/找回/恢复码：字段与文案严格照 App 模块01；恢复码只显示一次；密码规则；协议版本 |
| 02 养殖场 | 审核状态、驳回原因、资质图上传（FARM_QUAL）、地图选点（无 Key 时用示意地图/手填地址）、成员角色与栏舍调整 |
| 03 今日/日历/消息 | 待办状态词固定；日历月/周/日；消息中心双栏与未读数；全部养殖场视角 `scope=ALL` |
| 04 栏舍/批次 | 批次号查询代替扫码；跨场提示切换；员工不显示引种单价；入栏/转栏/死淘校验（数量不超存栏） |
| 05 繁育 | 配种/妊检/产仔/断奶/孵化状态机；活仔转批次；员工只读 |
| 06 饲喂/称重 | 餐次、计划量、库存不足提示；方案按生长阶段；称重抽样/逐头；生长曲线标准对比 |
| 07 巡检/诊断 | 今日巡检、补录、截止时间；异常上报照片视频（≤6、视频 1 段）；AI 诊断固定声明；转用药记录 |
| 08 免疫/用药/消毒 | 先到期先出批号；休药期与可出栏日期；删除用药影响可出栏需提交修改申请；消毒计划/任务 |
| 09 库存 | 结存、剩余可用天数、批号 FEFO；停用/召回；入库/出库/盘点/报损 |
| 10 收支/出栏/行情/报表 | 员工整块不渲染；重复记账提示；休药期拦截出栏；收款进度；盈亏与料肉比；AI 建议固定声明 |
| 11 AI/课堂 | SSE 流式、来源侧栏、评价、更正；课程 HLS 播放、倍速、续播；知识原文引用段落 |
| 通用 | 修改申请抽屉复用；U02 状态页；页面不存在 |

## 五、遇到冲突

| 冲突 | 处理 |
|---|---|
| 原型字段/数字与服务端不同 | 用服务端；不硬编码 |
| Web 文档与 App 文档不同 | 以 App 为准（业务规则、字段、文案） |
| 原型交互与服务端能力不足 | 选最接近的真实实现，在汇报里写明缺口；不要造假成功 |
| 共享组件缺属性 | 先用现有属性组合实现；确有必要的改动写进汇报，由主控统一改 |
