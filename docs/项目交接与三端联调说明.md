## 二、先做哪一项

| 顺序 | 工作 | 理由 |
|---|---|---|
| 1 | 服务端公共框架 + 模块01 账号、模块02 养殖场 | 登录、令牌、当前养殖场（X-Farm-Id）是所有页面的前提；App 联调也从这里开始 |
| 2 | 服务端管理端-01 审核、管理端-03 基础数据 | 新建养殖场要平台审核才能用；品类、兽药目录、禁用药、免疫模板、字典是各业务模块的下拉数据来源。上线前可先用 Flyway 初始化脚本灌数据 |
| 3 | 服务端模块03–11 按编号推进；同时启动 Web 管理端 | 管理端页面少（4 篇），先做出来就能在界面上审核、维护基础数据和上传课程，不必手改数据库 |
| 4 | Web 用户端 | 功能与 App 对应，可直接参照 App 的交互和 Mock 数据；服务端某模块完成后即可联调该模块 |

Web 不必等服务端全部写完：按 04 号第十七节，服务端先用 SpringDoc 生成 OpenAPI 并导入 Apifox，Web 在后端完成前用 Apifox 的模拟数据开发（模拟数据取 05 号统一示例数据，与 App 的 Mock 是同一套人和数据）。

## 四、三端怎么连起来

| 环节 | 做法 |
|---|---|
| 入口 | 全部经 Nginx 的 HTTPS 域名：App 接口 api.{域名}（代理 /api/v1）；Web 用户端 web.{域名}（静态页面 + 同源代理 /api/v1、/hls、高德安全密钥）；管理端 admin.{域名}（静态页面 + 代理 /admin/v1、/hls）；对象存储 files.{域名}（代理 MinIO）。Web 同源访问接口，不配跨域 |
| 环境 | dev（本机）、test（联调服务器，App 调试版与 Web 测试站连这里）、prod（正式） |
| 地址配置 | App：local.properties 的 zmt.baseUrl（末尾带 /）与 zmt.useMock；Web：.env.{环境} |
| 账号 | App 与 Web 用户端同一套账号（手机号 + 密码或短信验证码）；管理端独立管理员账号 |
| 认证 | 访问令牌放 Authorization: Bearer；App 用刷新接口 API-A06 换新令牌；Web 的刷新令牌放 HttpOnly Cookie，旧刷新令牌有 30 秒宽限期 |
| 公共请求头 | X-Farm-Id（当前养殖场）、X-Client（App 为 APP_ANDROID）、X-App-Version、Idempotency-Key（新增类提交防重）、X-Trace-Id；服务端可回 X-Min-App-Version、X-App-Download-Url 提示升级 |
| 响应格式 | 统一 {code, message, data, trace_id}；code 为 0 表示成功，错误码见 04 号第七节；联调排错时报 trace_id |
| 文件 | 照片、视频走 API-U05 上传，服务端存 MinIO；课程视频由 FFmpeg 转 HLS，App 与 Web 经 /hls 播放；私有文件用 files.{域名} 的签名临时地址 |
| 推送 | App 用极光 SDK 拿 registrationId，经 API-T20（PUT /api/v1/push-devices）上报，**别名由服务端绑定**；服务端用 AppKey + Master Secret 调极光 REST API 下发，消息附带 route、farm_id、biz_type、biz_id、message_id 等字段，App 点击后按 route 打开页面；Web 没有推送，看消息中心 |
| AI | 生产环境：App / Web → 服务端 → 阿里云百炼（千问）；问答用 SSE 流式返回（Nginx 对 /api/v1/ai/ 关闭缓冲，超时 180 秒）；语音识别也由服务端调用 |
| 短信 | 服务端调用阿里云号码认证 Dypnsapi（签名“恒创联众”，模板 100001–100005） |
| 地图 | App 用高德 Android SDK；Web 用高德 JS API 2.0（安全密钥经 Nginx 代理）；服务端用高德 Web 服务 Key 做逆地理等 |

## 五、App 切到真实服务端

| 步骤 | 做法 |
|---|---|
| 1 改地址 | local.properties：zmt.baseUrl=https://api.{测试域名}/，zmt.useMock=false |
| 2 关测试直连 | 清空 ai.dashscopeKey、ai.deepseekKey、aliyun.accessKeyId、aliyun.accessKeySecret（直连即自动关闭，AI、短信改走服务端接口）；否则调试包仍会自己去调千问和阿里云短信，和服务端的校验冲突 |
| 3 日期 | Mock 关闭后“今天”自动用真实日期（zmt.mockToday 只在 Mock 时生效） |
| 4 推送 | test 环境服务端配 debug 包对应的极光应用（包名 com.zhimu.slmp.debug）的 AppKey 与 Master Secret；prod 用 release 包（com.zhimu.slmp）那一个 |
| 5 联调顺序 | 01 账号（注册、登录、刷新令牌）→ 02 养殖场（创建、审核、切换、成员）→ 03 今日与消息、推送 → 04 栏舍存栏 → 05–08 生产登记 → 09 库存 → 10 收支报表 → 11 AI 与课堂；每个模块用所有者王建国、员工李明各走一遍 |
| 6 记录问题 | 字段、取值不一致：先查《App接口对接与待确认清单》，按“接口所属模块的服务端文档为准”改 App 或服务端；改动回写清单 |
| 7 回归 | 全量单测 `./gradlew testDebugUnitTest`；真机按模块冒烟；最后打 release 包（需签名）再回归一遍 |
