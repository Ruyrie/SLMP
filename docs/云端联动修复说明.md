# 云端联动修复（方案 A）

本轮保留 Android 多模块、Spring Boot 服务端与 Vue 用户/管理双工程，继续使用真实云端读写和实际北京时间。

## 数据与 App

- Android 登录和冷启动会恢复有效养殖场；没有上次养殖场时选择首个有效场，网络失败保留上下文并提供重试。
- 已完成短信认证后，重试进入只恢复养殖场，不重复消费验证码。
- V9_15 保留已有健康演示补丁；V9_16 补齐健康详情、库存流水、成本与待办，并补充迁移当天的健康案例。
- 健康关联修补会对缺失出库的演示记录一次性扣库存，重复执行不再扣；已有人工修改的记录不会重置。
- 消毒周期按真实日期生成后续任务；用药记录决定首页与批次详情的休药状态。
- V9_17 仅补最近七天的演示行情，来源为 `SEED`，不虚构交易、产仔或巡检异常。

## Web

- 管理端修复首次改密字段、路由循环、Cookie 会话恢复、退出以及验证码失败后的重试。
- 管理端独立默认使用 `/admin/v1` 和 `ADMIN_WEB`，构建不再依赖未跟踪环境文件来区分两端。
- 登录页图标样式只应用于图标，不再被说明文字的样式覆盖。
- 共享头像组件展示实际图片，加载失败时显示姓名首字；上传/删除同步到个人中心和顶栏。
- 用户列表、用户详情、用户端及管理端的养殖场成员接口补充 `avatar_url`。

## 更新与验证

`server/tools/deploy/update-full.sh` 用于已部署服务器的统一更新。更新包包含 Jar、Web 双端产物和 Nginx 配置，不含密码或第三方密钥。脚本备份数据库、旧 Jar、配置和 Web 页面后更新；新服务启动失败时恢复旧 Jar 与配置。

验证范围包括 Android 定向单测和 Debug APK、Web 双端类型检查/回归测试/生产构建、服务端相关单测、云端数据库副本迁移与重复执行检查，以及部署后的 API 和页面验证。检查结果以本轮交付回复为准。
